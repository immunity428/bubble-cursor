# アンケート実験アプリ（バブルカーソルあり／なし比較）

「バブルカーソルなし」「あり」の2条件で、同じアンケートと**エイム課題**を1回ずつ行ってもらい、
**クリックした点を点群とみなして、点と点のあいだのカーソル移動**を数値にします。

バブルカーソルの計算は、拡張機能版 `content.js` のアルゴリズム（論文の `min(ConD_j, IntD_k)`）をそのまま `js/bubble-cursor.js` に移しています。

## 動かし方

`index.html` を Chrome で開くだけで動きます（サーバー不要・オフライン可）。

1. 設定画面で参加者IDを入れて「実験を始める」
2. 説明 → 練習1ページ → アンケート本番（4ページ）→ エイム課題（練習5秒 → 本番15秒）→ 休憩 → もう一方の条件で同じ流れ
3. 最後の画面で **生データ (JSON)**、**区間データ (CSV)**、**エイム成績 (CSV)** を保存する

保存し忘れても、直近5件はブラウザ内に残り、設定画面の下から JSON を保存できます。

│   ├── dev-mode.js       開発者モード（クリックできる範囲の表示）
│   ├── cursor-logger.js  カーソル軌跡・クリックの記録

## エイム課題

アンケートは「読む・考える」時間が混ざるため、純粋なポインティングの速さと正確さを測るために入れています。

- 画面に円のターゲットを常に並べ（初期値 10個・直径 24px）、そのうち1つを**目標（オレンジ）**にする
- 目標に当てると、別のターゲットがランダムに次の目標になる。制限時間（初期値 15秒）まで繰り返す
- 目標以外を選んだら**誤選択**、何も選ばれなかったら**空振り**。目標はそのまま
- 配置と目標の順番は**乱数の種**で決まるので、同じ種なら両条件・全参加者で同じ並びになる（画面サイズが同じ場合）
- ターゲットは円として扱う（`data-bc-shape="circle"`）。バブルの IntD / ConD も論文どおり円で計算
- 設定画面で、秒数・ターゲット数・直径・乱数の種を変えられる。秒数を 0 にすると実施しない

ターゲットの数（混み具合）と大きさで、バブルカーソルの効き方が大きく変わります（論文の Distractor Density / Width にあたる）。条件をそろえて実施してください。

**エイム成績 (CSV)** には1ラウンドごとの `hits`（命中数）、`accuracy`（命中 ÷ クリック数）、`hits_per_s`、誤選択・空振りの数が入ります。
区間データでは `task = aim` の行が1回の命中（前の命中 → 次の命中）にあたり、`throughput_bps`（Fitts のスループット = ID ÷ 時間）も出ます。

## 開発者モード

各ターゲット（回答の点）を**どこからクリックすれば選べるか**を、画面に重ねて表示します。
レイアウトの確認や、ターゲットの配置・大きさを決めるときに使います。

- 設定画面の「開発者モード」にチェックを入れるか、`index.html?dev` で開く
- 実験中も **Alt+Shift+D**（Mac は Option+Shift+D）でオン/オフできる

| 表示 | 意味 | 切り替え |
| --- | --- | --- |
| 半透明の円 | その円の中のどこでクリックしても、**必ず**そのターゲットが選ばれる一番大きな円（中心はターゲットの中心） | Alt+Shift+C |
| 正確な範囲 | そのターゲットが選ばれる範囲そのもの。バブルカーソルは IntD（ターゲットの一番近い点までの距離）が最小のものを選ぶので、隣のターゲットとの中間で区切られた形（ボロノイ領域）になる | Alt+Shift+R |
| ラベル | ターゲットの ID と円の半径 | Alt+Shift+L |
| 情報パネル | 条件、最大半径、カーソル位置、いま選ばれるターゲット、IntD、円の半径、範囲の面積、いちばん小さい円 | Alt+Shift+H |

- 円の半径は、ターゲットの中心から 180 方向に線を伸ばし、はじめて別のターゲットが選ばれる（最大半径があるときは何も選ばれなくなる）までの距離の最小値です
- **バブルなし**の条件では、実際にはターゲットの上でしか選べないため、円を点線で描きます（バブルありなら選べた範囲の参考表示）
- 表示はすべてクリックを素通りするので、バブルカーソルの動きやクリックの記録には影響しません
- 計算はバブルカーソル本体と同じ距離の式です。ランダムな 3,000 点で本体の選択と一致し、円の中の点はすべてそのターゲットが選ばれることを確認しています（最大半径なし／40px の両方）
- 開発者モードを使うと、生データに `meta.devModeUsed: true` と `devmode` イベントが残り、結果画面と比較ページに注意が出ます。**本番のデータには使わないでください**（参加者に範囲が見えてしまうため）

## 記録するもの（生データ JSON）

| 項目 | 内容 |
| --- | --- |
| `samples` | カーソル座標 `t, x, y`。`pointermove` の `getCoalescedEvents()` を使うので、マウスのポーリングレート（125〜1000Hz）に近い細かさで取れる |
| `events` の `down` / `up` | マウスボタンを押した・離した時刻と位置（実際に手で押した位置） |
| `events` の `select` | 回答・「次へ」・「開始」が選ばれた出来事。`via` が `direct`（直接クリック）か `bubble`（バブルが補正） |
| `events` の `page` | ページを表示した時刻と、全ターゲット（選択肢・ボタン・エイムの円）の位置と大きさ |
| `events` の `aim-start` / `aim-goal` / `aim-end` | エイム課題の開始・目標の切り替え・終了 |
| `events` の `devmode` | 開発者モードのオン/オフ |
| `scroll` / `wheel` / `blur` / `resize` / `key` | 計測を乱す出来事（あとで区間を除外するため） |
| `meta` | 条件の順番、最大半径、画面サイズ、devicePixelRatio、UA など |

座標はビューポート座標（CSS px）、時刻は `performance.now()` と同じ基準の ms です。

## 区間の指標（区間CSV）

**区間** = ひとつ前に選んだ点でボタンを押した瞬間 → 次の点でボタンを押した瞬間。
エイム課題では目標に当てたクリックだけが点になります。`task` 列（`survey` / `aim`）で課題を区別します。
`pointermove` はカーソルが動いたときだけ届くため、**サンプルの間隔が 100ms を超えたら停止**とみなします。

| 列 | 意味 |
| --- | --- |
| `time_total_ms` | 区間の全時間（読む・考える時間を含む） |
| `time_active_ms` / `time_idle_ms` | カーソルが動いていた時間／止まっていた時間 |
| `time_final_move_ms` | 押す直前の「ひと続きの動き」の時間（最後に止まっていた位置から動き出して、押す前に止まるまで）。読む時間を除いた**移動時間**として使える |
| `dwell_before_press_ms` | 動きを止めてから押すまでの時間 |
| `dist_straight_px` / `path_px` | 2点間の直線距離／実際に動いた道のり |
| `straightness` | 直線距離 ÷ 道のり（1 に近いほどまっすぐ） |
| `speed_active_px_s` | 道のり ÷ 動いていた時間 |
| `speed_final_px_s` | 最後の動きの道のり ÷ その時間 |
| `speed_peak_px_s` | 最大速度（40ms の窓で計算） |
| `pauses` | 区間内で止まった回数 |
| `press_to_target_px` | 押した位置から選ばれたターゲットまでの距離。なし条件では 0、あり条件ではバブルがどれだけ助けたか |
| `target_dist_px` / `target_w` / `fitts_id` | 出発点→ターゲット中心の距離、ターゲットの大きさ、Fitts の難易度 `log2(D/W+1)`（W = 幅と高さの小さい方） |
| `miss_clicks` | 区間内で何も選ばれなかったクリック（空振り） |
| `wrong_selections` | エイム課題で目標以外を選んだ回数 |
| `throughput_bps` | エイム課題のみ。`fitts_id ÷ 区間時間(s)` |
| `revision` | 一度答えた質問の回答を変えたか |
| `included` | 条件別まとめに使うか（練習、「開始」ボタンへの移動、エイムの1回目、スクロールを含む区間は false） |

閾値は `js/analysis.js` の `DEFAULT_PARAMS` で変えられます。生データから作り直す場合:

```bash
node analysis/segments-from-json.js --pause 150 data/*.json > all_segments.csv
python analysis/aggregate.py all_segments.csv data/*_aim.csv
```

## 実験の設計で気をつけること

- **順序効果**: 同じアンケートを2回答えるので、2回目は内容を覚えていて速くなります。条件の順番は参加者IDの偶奇で自動的に入れ替わります（奇数: なし→あり、偶数: あり→なし）。人数は偶数にそろえてください
- **ページは画面に収める**: スクロールすると画面上の位置がずれるので、その区間は集計から除かれます。1ページ4問程度まで
- **画面とマウスをそろえる**: 全員同じPC・マウス・ポインタ速度設定・ブラウザの拡大率で。全画面での実施を推奨
- **キーボード操作は無効**: 実験中は Tab / Enter / Space で選べないようにしています
- **最大半径**: 初期値は 0（上限なし＝論文と同じ）。拡張機能版と同じ 200px にもできます。卒論ではどちらを使ったか明記してください
- **「開始」ボタン**: 説明画面ではどちらの条件でもバブルは無効です。開始ボタンの位置は両条件で同じなので、本番1問目への区間の出発点もそろいます
